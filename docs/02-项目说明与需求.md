# 项目说明与需求文档

> 本文档供 `/goal` 会话使用。目标：用 Claude 搭建一个**自托管、带 Web GUI 的类 Codex 编码 Agent 应用**。

## 一、项目背景与目标

参照 GitHub 上主流自托管 Agent 项目（OpenHands、AutoGPT、Open WebUI 等）的技术实现，搭建一个属于自己的、带 Web 界面的编码 Agent。

**一句话定位**：在浏览器里向一个编码 Agent 下发任务（如"修复这个 bug"、"实现某某功能"），Agent 自主调用工具（读写文件、执行命令、搜索代码），全程实时展示每一步的执行状态（流式输出、工具调用卡片、文件树、终端），结果可持久化回看。

**与本项目（F:\MyAgent）的关系**：当前工作目录为空，本项目从零搭建。用户平时通过 Claude Code 使用 `/goal` 发起建设任务，此文档是给 `/goal` 的输入。

## 二、核心场景（验收故事）

用户打开 Web 界面 → 新建会话 → 选择模型（Anthropic Claude / OpenAI / Ollama）→ 输入自然语言任务 → Agent 开始工作：
1. 界面实时流式显示 Agent 的思考/回复
2. 每个工具调用（读文件、写文件、执行命令）以**卡片形式**展示参数与结果，可展开查看
3. 右侧显示工作区**文件树**，被修改的文件高亮
4. 任务完成后可查看完整会话历史，支持恢复/重跑

## 三、功能需求

### 3.1 必须实现（MVP）
| # | 功能 | 说明 |
|---|---|---|
| F1 | 会话管理 | 新建/列表/删除会话，会话持久化（重启不丢） |
| F2 | 流式对话 | Agent 输出实时流式展示，支持 Markdown 渲染与代码高亮 |

| F5 | 权限审批 | bash 等高危工具执行前需用户确认（可在设置里改为自动允许） |
| F6 | 文件树面板 | 展示工作区目录结构，被修改文件高亮，可点击在 Monaco 中查看 |
| F7 | 多模型切换 | 至少支持 Anthropic Claude + OpenAI 兼容端点；API Key 可配置 |
| F8 | 停止/中断 | 运行中可随时停止 Agent 当前循环 |

## 四、技术架构（推荐选型，可微调）

```
┌─────────────────────────────────────────────┐
│  Web 前端 (React 19 + Vite + TS + Tailwind) │
│  组件：shadcn/Radix · Monaco · xterm.js     │
│  状态：zustand + TanStack Query             │
│  实时：Socket.IO client                     │
└────────────────────┬────────────────────────┘
                     │ HTTP + Socket.IO
┌────────────────────▼────────────────────────┐
│  后端 (Python FastAPI + Uvicorn + Pydantic) │
│  · Agent 引擎（工具调用循环）                │
│  · LiteLLM 统一 LLM 接入                     │
│  · 工具集：file / bash / grep / glob        │
│  · 权限审批中间层                            │
│  · SQLite + SQLAlchemy（会话持久化）         │
│  · Socket.IO 事件推送（agent/status/tool）  │
└─────────────────────────────────────────────┘
```

### 关键实时事件设计（Socket.IO）
| 事件 | 方向 | 说明 |
|---|---|---|
| `chat.message` | 服务端→前端 | 流式消息增量 |
| `agent.status` | 服务端→前端 | running / waiting_approval / done / error |
| `tool.start` / `tool.result` | 服务端→前端 | 工具调用开始/结束（含入参、结果） |
| `approval.request` / `approval.respond` | 双向 | 权限审批 |
| `file.changed` | 服务端→前端 | 文件变更，驱动文件树高亮 |

## 六、非功能需求

| 项 | 要求 |
|---|---|
| 部署 | 本机可一键启动（前端 npm run dev / build，后端 uvicorn）；提供 docker-compose 更佳 |
| 安全 | 工具执行限工作目录；bash 默认需审批；API Key 存后端配置（勿硬编码/入 git） |
| 性能 | 流式输出首 token 延迟 < 2s；工具调用结果秒级返回 |
| 兼容 | Windows 11 可运行（本项目环境 win32）；浏览器 Chrome/Edge 最新版 |
| 可维护 | 前后端代码注释适量，README 说明启动方式 |
| 语言 | 界面中文优先（可选英文） |
